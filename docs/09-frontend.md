**이 화면이 요구사항의 중심이다.** "실시간 캡처한 실제 쿼리를 PS의 바인드 변수화된 그룹
쿼리와 묶어 샘플로 쓴다"가 여기서 구현된다.

**샘플 출처 표시가 중요하다.** 4가지 출처가 있고 사용자는 구분해야 한다:

| 배지 | 출처 | 의미 |
|---|---|---|
| `최악` | `DT#<digest>/SLOWEST` | 관측 이래 가장 느린 실행. 35일 이후에도 생존 |
| `최근` | GSI1 `Q#` prefix | 최근 실시간 캡처 (리터럴 포함, 플랜 있음) |
| `PS 샘플` | `DigestText.ps_sample_text` | 실시간 캡처에 안 걸림. MySQL이 준 샘플. 절단 가능 |
| `열람 기록됨` | 정책 `full_restricted` | 리터럴 표시됨. **이 조회가 감사 로그에 남는다**는 것을 알린다 |
| `마스킹됨` | 정책 `masked`/`off` | 실행 불가. 정책 안내 + 설정 링크 |

`full_restricted` 인스턴스의 샘플은 **기본적으로 접힌 상태**로 표시하고, 사용자가 펼칠 때
`data.literal_view` 감사 이벤트를 남긴다. 목록을 스크롤하는 것만으로 감사 로그가 쌓이지
않게 하기 위함이다([08 §6.1](08-security-auth.md)).

샘플이 하나도 없는 경우(다이제스트 스냅샷만 있고 실시간 캡처도 PS 샘플도 없음)를 위한
빈 상태 문구: "이 쿼리는 임계값(2초)보다 빠르게 끝나 개별 캡처되지 않았습니다.
`performance_schema_max_digest_sample_age`가 짧으면 PS 샘플도 남지 않습니다."

**플랜 출처 배지** — 문구를 정확히 쓴다([ADR-006](03-decisions.md)).

| `plan_source` | 배지 문구 | 의미 |
|---|---|---|
| `for_connection` | **실행 중 캡처 (옵티마이저 플랜)** | 그 실행에서 옵티마이저가 선택한 플랜. **실제 처리 행수·단계별 시간은 아니다** |
| `rerun` | **사후 재실행 · 당시 플랜과 다를 수 있음** | 바인드 값·세션 변수·트랜잭션 스냅샷이 다르다 |
| `none` | **수집 실패: `<사유>`** | 사유를 그대로 표시 (thread_gone / not_explainable / timeout / denied) |

**플랜 출처 배지** — `plan_source` 를 사용자에게 그대로 보이지 않는다:

| `plan_source` | 배지 | 의미 |
|---|---|---|
| `for_connection` | (없음) | 실행 중 캡처. **RDS 에서는 나오지 않는다** |
| `rerun` | (없음) | 사후 재실행. 통계가 변했을 수 있다 |
| `rerun_as_select` | **근사** (주의색) | DML 의 조건절만 SELECT 로 바꿔 얻었다 — **쓰기 단계가 빠져 있다** |
| `none` | **플랜 없음** | `plan_error` 를 함께 보여준다 |

`rerun_as_select` 에 배지가 없으면 사용자가 UPDATE 의 완전한 플랜으로 오독한다.


**"실제 실행 플랜"이라고 쓰지 않는다.** `EXPLAIN`은 옵티마이저 플랜이고 실행 결과가 아니다.
과장은 오진을 만든다. `rerun` 배지는 노란 배경으로 항상 눈에 띄게 한다.

**플랜 트리 시각화 규칙**
- 노드 크기 = `rows_examined_per_scan` 로그 스케일
- 색: `access_type`이 `ALL`/`index` → 빨강, `range`/`ref` → 노랑, `eq_ref`/`const` → 초록
- `using_temporary_table` / `using_filesort` → 노드에 아이콘
- `cost_info.query_cost` 상위 3개 노드에 순위 배지
- 기존 `QueryPlanVisualization.tsx`의 접근을 계승하되, JSON v1/v2 스키마 차이를
  파서 계층에서 흡수한다(`planparse`가 백엔드에서 정규화한 형태를 받는 것이 더 낫다
  → 백엔드가 `plan_tree_normalized`를 함께 제공한다).

### 3.4 실시간 스트림 — `/live`

**진행 중인 쿼리를 보여준다** — 초기 설계는 **확정(finalize) 이벤트만** 방송했다.
확정은 쿼리가 processlist에서 사라진 뒤이므로, **50분째 돌고 있는 쿼리는 50분 동안 어느
화면에도 나타나지 않는다.** FR-UI-08("발생하는 즉시")이 지켜지지 않았다.
데이터는 이미 있다 — [05 §4.3](05-collector.md)이 최초 관측 시점에 `state=in_flight`로
선행 저장하고 [16 §2.2](16-cost.md)가 그 쓰기 비용까지 계산해 뒀다.
**저장은 하는데 방송을 안 하고 있었다.**

```
OBSERVED   (탐지 즉시) → WS { t:"slowq", state:"in_flight", record_id, duration_ms:<현재> }
TRACKING   (5초마다)   → WS { t:"slowq", state:"in_flight", record_id, duration_ms:<증가> }
FINALIZING (종료 확정) → WS { t:"slowq", state:"finalized", record_id, duration_ms:<확정> }
```
같은 `record_id`이므로 클라이언트는 행을 교체(upsert)한다.

```
┌────────────────────────────────────────────────────────────┐
│ 현재 실행 중 (3)                                    ⏸ 일시정지│
│ 🔴 51:23  orders-prd-01  shop  SELECT o.* FROM orders …     │
│ 🟠 04:07  users-prd-02   auth  UPDATE users SET …           │
│ 🟡 00:12  pay-prd-01     pay   SELECT SUM(amount) …         │
├────────────────────────────────────────────────────────────┤
│ 최근 완료                                                   │
│ 14:23:15  orders-prd-01  shop  4.21s  SELECT o.* FROM …     │
└────────────────────────────────────────────────────────────┘
```

- "현재 실행 중" 섹션의 경과 시간은 클라이언트에서 1초마다 증가시킨다(서버 푸시는 5초 주기).
- 최대 200행 유지(그 이상은 버림). 일시정지 버튼.
- 인스턴스·환경·최소 실행시간 필터를 WS 구독 메시지로 서버에 전달(클라이언트 필터링 아님 —
  대역폭 절약).
- 새 행에 하이라이트 애니메이션. `prefers-reduced-motion` 존중.

### 3.5 설정 - 부트스트랩 — `/settings/bootstrap`

```
1단계  대상 선택      인스턴스 다중 선택 (환경 필터, 미부트스트랩만 보기)
2단계  자격증명 소스   ○ RDS 관리형 시크릿 (12대 사용 가능)
                      ○ Secrets Manager ARN 지정
                      ○ 직접 입력 (1회, 저장되지 않음)
3단계  권한 모드      ○ least (권장) + 스키마 화이트리스트
                      ○ broad
4단계  계획 확인      실행될 SQL 전문 표시 (인스턴스별)
                      ⚠ prd 인스턴스 3대 포함 → 식별자 타이핑 필요
5단계  실행           진행률 WebSocket 스트림, 인스턴스별 성공/실패
```

- 4단계에서 SQL을 **접지 않고 전부** 보여준다. 스크롤이 길어도 접지 않는다.
- 직접 입력 폼은 `autocomplete="off"`, `type="password"`, 브라우저 저장 방지.
  제출 후 즉시 필드를 비운다.
- 실행 후 자동으로 자가진단을 돌려 결과를 보여준다.

### 3.6 인스턴스 상세 — 메트릭 탭

```
[실시간 · 자체 수집 · 5초]                    [CloudWatch · 60초 · 1~3분 지연]
 QPS / Threads_running / Lock waits            CPU / 연결 / 메모리 / IOPS / 지연
 (최근 60분, 메모리)                            (기간 선택: 1h 3h 6h 12h 1d 3d 1w 1mo)
```

두 영역을 **테두리·배경으로 명확히 분리**하고 각각 라벨을 단다(FR-MET-04).
같은 화면에서 "왜 그래프가 다르지"라는 혼란을 원천 차단한다.

CloudWatch 영역은 사용자가 그 탭을 볼 때만 호출한다(비용). 탭을 떠나면 폴링 중단
(`TanStack Query`의 `enabled` + `refetchIntervalInBackground: false`).

## 4. 실시간 통신

### 4.1 WebSocket 프로토콜

```
클라이언트 → 서버
  { "t": "auth",      "token": "<access_token>" }              // 연결 후 첫 메시지 필수
  { "t": "subscribe", "topics": ["slowq:env=prd", "status:inst=123456789012/ap-northeast-2/orders-prd-01"] }
  { "t": "unsubscribe", "topics": [...] }
  { "t": "ping" }

서버 → 클라이언트
  { "t": "ready",  "user": {...} }
  { "t": "slowq",  "data": { record_id, instance_id, env, duration_ms,
                             sql_preview,        // 항상 정규화 텍스트 (아래 참조)
                             app_digest, state } }   // state: in_flight | finalized
  { "t": "status", "instance_id": "...", "at_ms": ..., "metrics": { qps: 3200, ... } }
  { "t": "alert",  "data": { ... } }
  { "t": "bootstrap_progress", "job_id": "...", "instance_id": "...", "state": "..." }
  { "t": "pong" }
  { "t": "error",  "code": "unauthorized" | "rate_limited" | "topic_denied" }
```

- **인증**: 연결 직후 5초 안에 `auth` 메시지가 없으면 서버가 종료한다.
  토큰을 URL에 넣지 않는다(ALB 로그 유출 방지, T-13).
- **재인증**: **5분마다 토큰·권한을 재검증한다** (T-33). 최초 1회만 인증하면 그룹 강등·
  계정 비활성이 반영되지 않아 WS 연결이 사실상 무기한이 된다. 실패 시 연결을 종료하고
  클라이언트가 재인증한다. 권한 변경 시 서버가 해당 사용자의 연결을 강제 종료한다.
- **마스킹**: 브로드캐스트 메시지는 응답 직렬화 래퍼를 타지 않는다(T-22).
  → **`slowq`의 `sql_preview`는 항상 정규화 텍스트만 담는다.** 리터럴이 필요하면 클라이언트가
  HTTP로 상세를 조회한다(그 경로에 권한·감사가 걸려 있다). 사용자별로 다른 페이로드를
  만들지 않으므로 브로드캐스트가 단순해지는 이득도 있다.
- **인가**: `subscribe` 시 **토픽별 인가 함수**로 판정한다
  ([13 §3](13-api-spec.md) 인가 매트릭스). 거부는 `topic_denied`.
  와일드카드·접두 구독(`slowq:*`)은 거부한다.
- **하트비트**: 클라이언트 30초 ping, 서버 60초 무응답 시 종료.
- **재연결**: 지수 백오프(1s → 30s) + 지터. 재연결 시 구독 자동 복원.
  토큰이 만료됐으면 갱신 후 재연결.
- **백프레셔**: 서버는 클라이언트당 송신 큐 상한(1000)을 두고, 초과 시 오래된
  `status` 메시지를 버린다(`slowq`/`alert`는 버리지 않는다).
- **레이트 리밋**: 클라이언트당 구독 토픽 최대 50개.

### 4.2 폴링과의 역할 분담

| 데이터 | 방식 |
|---|---|
| 실시간 지표, 슬로우 쿼리 스트림, 알림, 잡 진행률 | WebSocket |
| 목록·상세 조회, 설정, 리포트 | HTTP + TanStack Query |
| CloudWatch 메트릭 | HTTP, 탭 활성 시 60초 폴링 |
| Athena 결과 | HTTP 시작 → **HTTP 폴링** (2초 간격) → HTTP 결과 조회. WS 통지를 쓰지 않는다 ([ADR-015](03-decisions.md)) |

## 5. 성능 설계 (NFR-P-07)

| 문제 | 대응 |
|---|---|
| 슬로우 쿼리 1만 행 목록 | TanStack Virtual, 행 높이 고정, `content-visibility: auto` |
| 4만 포인트 시계열 | uPlot canvas. 데이터는 `Float64Array`로 전달(객체 배열 금지). API가 병렬 배열로 주므로 변환 불필요 ([13 §2.5](13-api-spec.md)) |
| 500개 인스턴스 카드 | 가상 그리드 + 기본 환경 필터. 스파크라인은 공유 canvas |
| 큰 플랜 JSON 렌더 | 트리 노드 지연 확장(기본 3레벨), 원본 JSON은 요청 시 로드 |
| 초기 번들 | 라우트별 코드 스플리팅. uPlot·sql-formatter·plan viewer는 지연 로드 |
| WebSocket 메시지 폭주 | 클라이언트에서 16ms 배칭 후 1회 렌더 (`requestAnimationFrame`) |
| SQL 포맷팅 비용 | 웹 워커에서 처리(큰 SQL은 메인 스레드 블로킹) |

목표: 초기 LCP 2.5초, 초기 JS < 250KB gzip, 상호작용 INP < 200ms.

## 6. 상태 관리

```
서버 상태   → TanStack Query (queryKey 에 필터 전부 포함)
URL 상태    → useSearchParams (필터·기간·정렬·페이지)
실시간 상태 → WS 이벤트를 받아 TanStack Query 캐시를 직접 갱신
              (queryClient.setQueryData) + 별도 ring buffer store(실시간 지표)
로컬 UI     → useState / useReducer
전역 클라이언트 상태 → Zustand 최소 사용 (테마, 사이드바, WS 연결 상태만)
```

전역 상태 라이브러리를 최소로 쓰는 이유: 이 앱의 상태는 대부분 서버 상태다.
서버 상태를 전역 스토어에 복사하면 동기화 버그가 생긴다.

## 7. 접근성

- 전 화면 키보드 내비게이션. 포커스 트랩(모달), 스킵 링크.
- 차트는 대체 표현 제공: `<table>` 형태의 데이터 요약을 `aria-describedby`로 연결.
- 색만으로 의미를 전달하지 않는다(플랜 노드 색 + 아이콘 + 텍스트 라벨 병기).
- 대비 4.5:1 이상. 다크·라이트 양쪽 검증.
- `prefers-reduced-motion` 존중.
- 스크린리더 라이브 영역: 실시간 스트림은 `aria-live="polite"`, 알림은 `assertive`.

## 8. 에러·빈 상태

**모든 화면은 4가지 상태를 정의한다**: 로딩 / 빈 / 에러 / 부분 실패.

| 상황 | 화면 |
|---|---|
| 인스턴스 없음 | "탐색된 인스턴스가 없습니다" + AWS 설정 링크 + 권한 진단 링크 |
| 수집 실패 인스턴스 | 자가진단 결과 요약 + 해결 방법 + "재점검" 버튼 |
| 슬로우 쿼리 없음 | "이 기간에 임계값을 넘은 쿼리가 없습니다" + 임계값 표시 + 다이제스트 목록 링크 |
| 다이제스트에 샘플 없음 | [§3.1](#31-다이제스트-상세--digestsappdigest) 문구 |
| Athena 조회 중 | 진행 시간 + 예상 스캔량 + 취소 버튼 |
| Athena 실패 | 에러 요약(내부 SQL 미노출) + 재시도 |
| CloudWatch 예산 초과 | "캐시된 데이터를 표시합니다" + 마지막 갱신 시각 + 설정 링크 |
| AI 예산 초과 | 남은 예산 + 다음 리셋 시각 |
| 권한 부족 | 무엇이 필요한지 명시 (403 응답의 `required_role`) |
| WS 끊김 | 상단 배너 "실시간 연결 끊김 · 재연결 중" |

**에러 메시지에 내부 정보를 넣지 않는다** — SQL 전문, 스택 트레이스, 내부 ARN은 로그에만.
사용자에게는 상관관계 ID(`request_id`)를 보여주고, 지원 요청 시 그걸로 로그를 찾는다.

## 9. 디자인 방향

- **밀도 우선.** 이 도구는 감상용이 아니라 조사용이다. 여백보다 정보량.
  표 행 높이 32px, 폰트 13~14px, 등폭 폰트는 SQL·식별자·수치에만.
- **환경 색 고정**: prd = 빨강 계열, stg = 주황, dev = 파랑. 전 화면 동일. 배지 + 텍스트 병기.
- **심각도 색**: 초록/노랑/주황/빨강 4단계. 색맹 대응으로 아이콘 병기.
- **숫자 정렬**: 우측 정렬 + 등폭 + 자릿수 구분. 큰 수는 축약(8.2M) + hover 시 전체.
- **시간 표기**: 목록은 상대 시간(3분 전), hover·상세는 절대 시간(KST + UTC 병기).
  타임존 혼동이 이런 도구의 고질적 버그원이다.
- **다크 모드 기본.** 이 화면을 보는 시간대가 대체로 새벽이다.

세부 시각 언어는 구현 시 `ui-ux-pro-max` / `frontend-design` 스킬을 참조한다.
